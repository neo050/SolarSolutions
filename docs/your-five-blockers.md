## 1 · אירוח (Hosting)

**למה זה חסום:** GitHub Pages מגיש קבצים סטטיים בלבד. הוא לא יכול להריץ את נקודת הקצה
ללידים ולא להנפיק 301 אמיתי. שני אלה כבר כתובים אצלנו ומחכים לסביבה שתריץ אותם.

### מה בדיוק לעשות

**ההמלצה: Cloudflare Pages.** חינם בהיקף הזה, מריץ את הפונקציה, תומך בהפניות ובכותרות
אבטחה — כולם כבר קיימים בקוד.

1. פתח חשבון ב־<https://dash.cloudflare.com> (אם אין).
2. **Workers & Pages → Create → Pages → Connect to Git** → בחר את הריפו הזה.
   הגדרות בנייה: Framework `Astro` · Build command `npm run build` · Output `dist` ·
   Root directory `site`.
3. **Workers & Pages → KV → Create namespace**, בשם `LEADS`.
4. בפרויקט: **Settings → Functions → KV namespace bindings** → משתנה `LEADS` → קשר לזה שיצרת.
5. **Settings → Custom domains** → הוסף `rnrg.co.il` ו־`www.rnrg.co.il`.
   Cloudflare יראה לך אילו רשומות DNS לשנות. **אל תשנה DNS עד שאישרנו את ה־Staging.**

**חלופה:** Netlify עובד באותה מידה. אותם קבצים `_redirects` ו־`_headers`.
**להישאר ב־GitHub Pages:** אפשרי, אבל אז הטופס עובד רק דרך וואטסאפ ואין 301 אמיתי —
ההפניות יהיו meta-refresh, שמעבירות חלק מערך הקישורים ולא את כולו.

### מה לשלוח לנו
- שם הפרויקט ב־Cloudflare, וכתובת ה־`*.pages.dev` שנוצרה.
- אישור שה־KV בשם `LEADS` נוצר וקושר.
- לאיזו כתובת מייל אתה רוצה שההתראה על ליד חדש תגיע.

### מה משתחרר אצלנו
- פריסת Staging תוך שעה.
- `PUBLIC_LEAD_ENDPOINT` מוגדר → הטופס עובר לשליחה לשרת עם אישור קליטה אמיתי, במקום
  מסירה לוואטסאפ.
- 13 ההפניות עוברות ל־301 אמיתי.
- כותרות האבטחה וה־CSP נכנסות לתוקף.
- בדיקות הלידים מקצה לקצה על סביבה אמיתית.

## 2 · GA4 + Google Tag Manager  ← **עשה את זה השבוע**

**למה זה דחוף מהשאר:** כל שכבת המדידה בנויה ועשרה אירועים כבר נכנסים לתור. חסר רק מזהה.
כל שבוע בלי מדידה הוא שבוע של נתוני בסיס שאי אפשר לשחזר בדיעבד — ובלי בסיס לא תהיה
דרך להוכיח שהאתר החדש שיפר משהו.

**זה שווה לעשות על האתר הקיים, עוד לפני המעבר.**

### מה בדיוק לעשות

1. <https://analytics.google.com> → צור חשבון ונכס (Property) בשם `RNRG`.
   Data stream → Web → `https://rnrg.co.il` → **העתק את ה־Measurement ID** (`G-XXXXXXXXXX`).
2. <https://tagmanager.google.com> → צור חשבון ומכולה (Container) מסוג Web עבור `rnrg.co.il`
   → **העתק את ה־Container ID** (`GTM-XXXXXXX`).
3. במכולה: **Tags → New → Google Analytics: GA4 Configuration** → הדבק את ה־Measurement ID
   → Trigger: All Pages → Save → **Submit** (בלי Submit שום דבר לא חי).

זה הכול. את הגדרת עשרת האירועים וסימונם כהמרות נעשה אנחנו — הם כבר נשלחים מהקוד.

### מה לשלוח לנו
- `GTM-XXXXXXX`
- `G-XXXXXXXXXX`
- הזמנה כ־Editor לשתי המערכות (למייל שנמסור), אם תרצה שנגדיר את האירועים בעצמנו.

### מה משתחרר אצלנו
- הפעלת המדידה על האתר **הקיים** מיד — מתחילים לצבור בסיס השוואה.
- הגדרת עשרת האירועים ב־GTM וסימון `generate_lead` ושלושת אירועי המסלולים כהמרות.
- אימות ב־GA4 DebugView שכל אירוע באמת נורה — פריט שכרגע חסום ב־QA Checklist.

## 4 · הגבלת מפתח Google Maps

**למה זה חסום:** המפתח גלוי בקוד המקור. כך זה תמיד עם מפתחות בצד לקוח — אי אפשר להסתיר
אותם. ההגנה היחידה היא הגבלת HTTP referrer, שנעשית בקונסולה ולא בקוד.

**זו בדיקה של חמש דקות.**

### מה בדיוק לעשות
1. <https://console.cloud.google.com/apis/credentials> → מצא את המפתח
   שמתחיל ב־`AIzaSyCgEhKy…`
2. **Application restrictions → Websites** → הוסף:
   `https://rnrg.co.il/*` , `https://www.rnrg.co.il/*` , וכתובת ה־`*.pages.dev` לזמן Staging.
3. **API restrictions → Restrict key** → סמן רק `Maps JavaScript API` ו־`Places API`.
4. **Billing → Budgets & alerts** → הגדר התראה. גם מפתח מוגבל שווה לנטר.

### מה לשלוח לנו
- אישור שההגבלה הוגדרה (צילום מסך מספיק).
- אם המפתח כבר נוצל לרעה — צור מפתח חדש ושלח אותו; נחליף.

### מה משתחרר אצלנו
- סגירת פריט אבטחה P0.
- השלמת השדה עם השלמת כתובת אוטומטית בטופס הסולארי.

## 5 · הדומיין הישן

**למה זה חסום:** שני טפסים באתר הישן הפנו ל־`neo050.github.io/SolarSolutions`. אם הדומיין
עדיין חי ומאונדקס, הוא מתחרה ב־rnrg.co.il על אותו תוכן בדיוק — וגוגל עשוי להעדיף אותו.

   זה מכבה אותו לחלוטין.

### מה לשלוח לנו
- האם הוא חי, וכמה עמודים מאונדקסים.
